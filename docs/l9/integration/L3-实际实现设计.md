# L3 实际实现设计

> 状态：已实现。本文以当前 `main` 的代码、测试和已提交人格资产为权威依据，对应
> [Issue #107](https://github.com/mindcarver/pengine/issues/107) 与
> [PR #108](https://github.com/mindcarver/pengine/pull/108)。

本文只说明 L3 如何真正进入 Pengine 运行时。L3 是“怎样发散、筛选、收敛和推进”的创作决策方法，不是剧情事实、创作者传记、角色模板或独立验收闸门。本次不设计 L5/L6。

## 1. 运行因果链

```text
personas/<persona>/l3.md
  → manifest 文件 hash + package_sha256 + snapshot_sha256
  → data/persona-snapshots/<snapshot_sha256>/l3.md
  → PersonaCatalog.load_stage_context()
  → v3: /persona/l3.md 完整正文
  → Worker 组装一次 Deep Agents 只读工作区
  → 专业 Agent 按阶段语义使用 L3
  → 候选结果仍必须通过 schema / Canon / L4 / 连续性 / Gate
```

L3 不直接写数据库，也不能直接批准业务 checkpoint。它影响模型如何在尚未锁定的创作空间中做决策；业务层仍以结构校验、独立审核和持久化事务决定什么能推进。

## 2. 资产合同与失败关闭

Persona v3 的 `l3.md` 必须满足：

- 是 manifest 八文件固定集合之一，文件 SHA-256 必须与 manifest 一致；
- 必须具有创作手法、认知路径、明确短板和摘要等必需标题；
- 必须同时有“已确认”状态和归属标记，出现待确认内容时拒绝加载；
- 完整文本不得超过 8,000 字符；
- 阶段人格上下文总长度超过配置上限时，以 `stage_context_too_large` 失败关闭，不静默截断。

上述逻辑集中在 `src/pengine/personas.py` 的 `validate_persona_package()`、`_validate_required_structure()`、`_validate_l3()` 和 `_enforce_context_limit()`。

## 3. 快照与版本兼容

| Persona schema | 新任务可选 | 运行时路径 | 文本形态 |
| --- | --- | --- | --- |
| v3 | 是 | `/persona/l3.md` | 完整、逐字、不摘要 |
| v2 | 否，只恢复旧 snapshot | `/persona/l3-summary.md` | 历史摘要投影 |
| v1 | 否，只恢复旧 snapshot | `/persona/l3-summary.md` | 历史摘要投影 |

创建任务时，应用把已验证的人格包复制到内容寻址快照目录。后续修改源目录中的 `l3.md` 不会改变旧任务；要让新内容生效，必须更新文件 hash、`package_sha256`、人格版本，并新建任务。

## 4. 阶段语义

`src/pengine/agents.py` 的 `_L3_POLICY` 对生成、修复和审核专业 Agent 使用同一套边界，但各阶段的可用权限不同：

| 阶段 | L3 允许做什么 | L3 明确不能做什么 |
| --- | --- | --- |
| `selecting_l0_variant` | 读取完整 L3，但仅保留方法边界 | 添加、改名、调权或重选 L0 变体 |
| `generating_story_outline` | 在未锁空间中比较实质不同路径，筛选后收敛一条主因果线 | 输出废弃方案或私有推理 |
| `generating_character_relationships` | 用人物可信度、处境、关系和因果可执行性筛选 | 把创作者方法复制为角色人格 |
| `generating_episode_outline` | 在已批准方向内细化集数义务和推进 | 重开故事方向或改写已批准上游 |
| `generating_episode_scripts` | 在 StoryContract、SeriesBible、SeriesState 和已批前缀留白内生长动作、台词和场面 | 改变锁定事实、关系、时间线、线索含义或后续义务 |
| 修复子 Agent | 只修复审核已确认的问题 | 扩大修改面、再发散或重开上游 |
| Reviewer / L0 / L4 Gate | 知道 L3 的越权边界 | 把“像不像 L3”当作通过或拒绝证据 |

权限顺序为：用户要求和锁定 Canon → L0 → 创作者确认的 L4 硬规则 → L3 → Soul。L3 还必须让位于已批准 checkpoint、StoryContract、SeriesBible、SeriesState、生产参数和已批剧本前缀。

## 5. 提示词与文件挂载的真实边界

这一层不是简单写进 `project.md` 就结束：

- `Worker._persona_files()` 从同一不可变 snapshot 组装工作区，v3 的 L3 在共享只读 VFS 中只有一份 `/persona/l3.md`；
- 九类生成、修复、审核专业 Agent 的 system prompt 都包含 `_L3_POLICY`，并可通过 `read_file` 读取完整 L3；
- `workflow_supervisor` 只做阶段编排，不注入 L3 正文，也不以人格模仿方式替代专业 Agent；
- Story/Outline 两条直接结构化补丁调用不运行 Deep Agent VFS：它们内联完整 Project 和 Soul，带入 L3 修复边界，**但不内联 L3 正文**；补丁只能处理 Reviewer 已确认的问题；
- 纯结构化结果序列化重试明确禁止改内容，因此不重复注入人格正文。

这个区分很重要：“L3 已经加载到任务工作区”只证明运行时组装成功，不能单独证明模型已语义采用、候选已通过或成品已交付。

## 6. 存储与可观测性

L3 正文只存在源人格包和任务快照中。`model_calls` 和 Langfuse 元数据只记录：

- `persona_schema_version`、`persona_id`、`persona_version`、`persona_snapshot_sha256`；
- `l3_sha256`、`l3_char_count`、`l3_mount_path`；
- `l3_full_text_mounted`。

Schema 21 为 `model_calls` 增加了后四个 L3 字段。它们不保存 L3 正文或摘录。`l3_full_text_mounted=true` 只表示 Worker 确认快照中有完整 v3 L3；`DeliveryReport` 不增加 L3 Gate，只保存人格快照身份与已定义的 L0/L4 Gate。

## 7. 代码责任映射

| 路径 | 当前责任 |
| --- | --- |
| `contracts/persona-package.schema.json` | v3 manifest 与八文件合同 |
| `src/pengine/personas.py` | L3 结构/状态/归属/长度校验，快照解析，v3 完整投影，上下文上限 |
| `src/pengine/worker.py` | 快照绑定、共享只读人格文件、L3 安全审计元数据 |
| `src/pengine/agents.py` | 阶段化 L3 方法边界、修复范围、Reviewer 非 Gate 边界 |
| `src/pengine/model_calls.py` / `observability.py` / `repository.py` | 模型调用元数据传递、观测和 Schema 21 持久化 |
| `src/pengine/schemas.py` | 交付报告不新增 L3 Gate 的公开合同 |
| `personas/shouzhuo/l3.md` | 已确认的守拙 L3 运行资产 |

## 8. 验收方法

确定性回归：

```bash
uv run pytest tests/test_personas.py tests/test_agents.py tests/test_worker.py \
  tests/test_model_calls.py tests/test_repository.py -q
```

关键证据包括：

- 四个生成阶段得到逐字完整 `/persona/l3.md`，不存在 `l3-summary`；
- 待确认、缺少归属或超过 8,000 字符时失败关闭；
- 所有专业提示词都保留 L3 方法和权限边界；
- 直接补丁提示词不泄露 L3 正文；
- 审计行只保存 hash、字符数、路径和挂载布尔值。

真实模型 A/B/C 是显式 opt-in：

```bash
PENGINE_RUN_L3_ABC=1 uv run pytest -m live_model \
  tests/live/test_l3_persona_e2e.py -vv -s
```

该 live 测试用来检查相同输入下的无 L3、旧摘要和完整 L3 差异，但仍不能以单次模型输出代替持久化与 Gate 证据。
